# Analytics & AI — RBAC Matrix

**Date:** 2026-08-18 · **Method:** live HTTP probe, not code reading.
**Coverage:** 26 roles × 77 endpoints + anonymous + bad-token = **2 156 probes**.

Generated by `backend/scripts/audit/rbac-probe.mjs`. Every row is an observed status code from a token
minted for a real, active account holding that role — not an inference from the policy table.

## Method

One active account per role is selected from `user_roles` (roles are many-to-many; the probe reads the
junction, never `users.role`). A token is minted with the backend's own `JWT_SECRET`, then every endpoint
is called with it. Requests are paced under the server's 300/min limit — an unpaced first run collected
429s from the fifth role onward and reported "no access" for roles that in fact had it, which would have
been a **false PASS on the security matrix**.

## Expected semantics

| Code | Meaning |
|---|---|
| 200 | allowed |
| 401 | unauthenticated |
| 403 | authenticated but not authorized |
| 404 | resource genuinely absent |
| 501 | route exists, capability not implemented (no backing table) |

## Headline results

- **0 × 5xx** across all 2 156 probes.
- **0 × 404** — no endpoint in the matrix is missing.
- **Anonymous: 401 on all 77. Bad token: 401 on all 77.**
- Only `admin` and `super_admin` reach all 77.
- A plain `employee` reaches **4**: two celebration endpoints (birthday wall, open by design),
  `/analytics/satisfaction` and `/dashboard/leave-summary` — both verified aggregate-only, carrying no
  named individuals.

## Fixed in this pass

`/api/v1/intelligence/*` (46 endpoints) was mounted with `verifyToken` and **no permission policy**. A
plain `employee` received **200** from `/intelligence/roles` (the entire role table, all companies) and
`/intelligence/rules` (rule-engine configuration). Both now return **403**. The mount carries
`intelligencePolicy` — deny-by-default at `admin:view`, with per-domain rules for audit, documents,
projects, finance, reports, approvals, settings, servicedesk, notifications and branches.

  privileged unguarded routes **rises**.

## Note on the low-privilege fixture

`e2e-mint-token.mjs` selects its account via the **`E2E_LOGIN_EMAIL` env var**, not a `--role` flag, and
silently ignores unknown argv. Passing `--role employee` mints a **super_admin** token, and a 200 then
reads as an auth leak. The probe reads the role set back from `user_roles` and asserts it before trusting
any token.
