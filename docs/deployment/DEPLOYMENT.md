## Architecture

| Layer    | Technology         | Target production URL |
|----------|---------------------|------------------------|
| Frontend | React 19 + Vite 8   | `https://erp.manifest-tech.in` |
| Backend  | Node.js + Express   | `https://api.manifest-tech.in` |
| Database | PostgreSQL          | Render-managed Postgres (Path A) or any Postgres via `DATABASE_URL`/`DB_HOST` (Path B) |

Two supported deploy paths exist in this repo, both hosted as **separate services on separate subdomains** (the frontend calls the API cross-origin via `VITE_API_URL` — there is no server-side proxy in either path):

- **Path A — Render**, config: `Pulse/render.yaml`. This is the canonical Blueprint; DB, backend, and frontend are all defined there and Render provisions the managed Postgres automatically (`DATABASE_URL` is injected — you never set `DB_HOST` etc. on this path).
- **Path B — Railway**, config: `Pulse/backend/railway.toml` + `Pulse/frontend/railway.toml`. Bring your own Postgres (any managed provider) and set discrete `DB_HOST`/`DB_PORT`/`DB_NAME`/`DB_USER`/`DB_PASSWORD` vars, or a `DATABASE_URL`.

A third config, `Pulse/docker-compose.yml` + `Pulse/frontend/nginx.conf`, exists for **local pilot demos and the CI "Docker Build & Boot" job only** — it same-origin-proxies `/api` through nginx to an internal container and is not used for real production traffic today.

## Backend Deployment

### Render (Path A)

Everything is defined in `Pulse/render.yaml` — connect the repo in the Render dashboard, point it at that Blueprint, and it provisions the DB + backend + frontend together. After the first deploy, set these `sync: false` values in the dashboard (they're deliberately not committed):

| Variable | Where it comes from |
|---|---|
| `BACKUP_S3_BUCKET` | your off-host backup bucket |
| `ALERT_WEBHOOK_URL` | Slack/Discord/PagerDuty incoming webhook (optional) |
| `VITE_API_URL` (frontend service) | `https://api.manifest-tech.in/api` |

`JWT_SECRET` and `ENCRYPTION_KEY` are auto-generated by Render on first deploy (`generateValue: true`) — rotate them from the dashboard if ever needed, don't hardcode them anywhere.

Bind the custom domains (`erp.manifest-tech.in`, `api.manifest-tech.in`) to the two services in the Render dashboard; Render issues and renews the TLS certificates automatically once the DNS CNAME verifies.

### Railway (Path B)

`backend/railway.toml` builds with nixpacks and runs `node server.js`, healthchecking `/api/health`. Set these in the Railway dashboard → Variables:

| Variable | Value | Required |
|---|---|---|
| `DATABASE_URL` *or* `DB_HOST`+`DB_PORT`+`DB_NAME`+`DB_USER`+`DB_PASSWORD` | your Postgres connection details | ✅ Critical |
| `DB_SSL` | `true` (unless your Postgres provider doesn't speak TLS) | Required if using discrete DB vars |
| `JWT_SECRET` | 32+ random chars — `node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"` | ✅ Required |
| `ENCRYPTION_KEY` | 32-byte key — `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` | ✅ Required |
| `NODE_ENV` | `production` | Required |
| `FRONTEND_URL` | `https://erp.manifest-tech.in` | Required — CORS + email links |
| `PORT` | set automatically by Railway | Auto-set |

> **Most common error:** `ECONNREFUSED ::1:5432` means the database isn't configured — set `DATABASE_URL` or the discrete `DB_*` vars.

Deploy: push to the branch Railway is watching (`git push`) — it auto-builds via `railway.toml`.

### Verify (either path)

```
GET https://api.manifest-tech.in/api/health
```
should return `{ "status": "ok", ... }` once migrations have run (they run automatically on boot — see `runMigrations()` in `server.js`). Follow up with `backend/scripts/smoke-prod.js` (`BACKEND_URL=https://api.manifest-tech.in node scripts/smoke-prod.js`) for a fuller check.

## Frontend Deployment

### 1. Environment variable (build-time — Vite bakes this into the bundle, it is not read at runtime)

| Variable | Value |
|---|---|
| `VITE_API_URL` | `https://api.manifest-tech.in/api` |

### 2. Build settings

| Setting | Value |
|---|---|
| Root directory | `frontend` |
| Build command | `npm ci && npm run build` (Render) or per `frontend/railway.toml` |
| Output directory | `dist` |

### 3. Deploy

Push to the branch the platform is watching — both Render and Railway auto-deploy on push per their respective config files. There is no separate manual deploy step; if you change `VITE_API_URL`, you must trigger a rebuild (a plain redeploy without a new build will keep the old baked-in value).

## Troubleshooting

### `connect ECONNREFUSED ::1:5432`
**Cause:** no database configured — neither `DATABASE_URL` nor `DB_HOST`/`DB_PASSWORD` is set.
**Fix:** Render sets `DATABASE_URL` automatically via the Blueprint; on Railway/self-managed, set it (or the discrete `DB_*` vars) in the dashboard.

### `Invalid token` / 401 on all requests
**Cause:** `JWT_SECRET` missing, or different between the process that issued the token and the one verifying it (e.g. after a redeploy that regenerated it).
**Fix:** Confirm `JWT_SECRET` is set once and stays stable across deploys — Render's `generateValue: true` only generates it on first deploy, not on every deploy.

### CORS errors in the browser console
**Cause:** `FRONTEND_URL` not set on the backend, or it doesn't exactly match the frontend's origin.
**Fix:** Set `FRONTEND_URL=https://erp.manifest-tech.in` (no trailing slash) on the backend service.

### Login returns `Invalid email or password`
**Cause:** either a genuinely wrong password, or (on a fresh deploy) migrations/seed didn't run and the expected account doesn't exist yet.
**Fix:** Check the platform's deploy logs for migration errors; confirm the database was reachable *before* the first deploy so `runMigrations()` could complete.

### `₹undefined` in payroll / finance
**Cause:** a numeric field arrived from the API as `undefined`/a string instead of a number.
**Fix:** amounts go through `formatINR(value || 0)` on the frontend — confirm the backend route returns a numeric field, not a missing or stringified one.

## Local Development

```bash
# Backend
cd backend
npm install
# .env needs DB_HOST, DB_USER, DB_PASSWORD (see .env.example)
npm run dev   # nodemon server.js on port 5000

# Frontend
cd frontend
npm install
# .env defaults VITE_API_URL to http://localhost:5000/api
npm run dev   # Vite on port 5173
```

Schema lives in `backend/src/database/migrations/` (applied on boot) with `backend/src/database/baseline.sql` as the from-zero bootstrap for fresh databases — see `Pulse/docs/deployment/` and the migration-baseline notes in project memory for how the two relate.
